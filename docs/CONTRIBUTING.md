# Contributing to Tobira

You want to contribute to Tobira by suggesting or implementing features, fixing bugs, improving documentation or in some other way? Great! Please take a minute to read the following contribution guidelines.

## New feature? Talk to us first!

Tobira is open source, values many forms of contribution, and exists to serve the Opencast community.
*However*, since Tobira is a user-facing application, we recognize that a coherent UI/UX vision, rather than a patchwork of features, will benefit everyone in the long run.
Therefore, we ask you to **propose new features, ideas and non-trivial UI/UX changes [by opening an issue](https://github.com/elan-ev/tobira/issues) first** and wait for feedback before implementing.

That way, we can discuss them before anyone invests significant time.
This saves you time and frustration if we end up rejecting a PR because it doesn't fit Tobira's vision.
Additionally, a big PR opened with the expectation that it will be merged makes for a poor starting point: 
it anchors the discussion on a finished implementation, leaves little room to shape the idea, and mixes UX debate with code review.

PRs that skip this step may be closed until the idea has been discussed and consensus has been reached.
This is not a rejection of the idea or code, just a request to talk it through first.

Of course, bug fixes, docs improvements and other small changes are welcome as direct PRs.
If in doubt, just ask in an issue.
